# 本体模型协同推演工作模式（Local-LLM Co-Derivation）

> 用途：OpenSPUM 各层的代码增量（L0 / L1 / L2 / 实验脚本）统一按本模式推进。
> 一句话：**主 agent 写接口规范 → 本地模型产出草稿 → 主 agent 审核判定 → 重写落地 → 逐位验证 → 冻结锚点。**
> 本地模型只作「骨架生成器」，**正确性基准永远是 CPU 参考实现**，不是本地模型。

## 1. 五步流程

### 步骤 1 — 主 agent 写接口规范（spec）

规范写成**纯文本文件**（不写进仓库，放临时目录），六个小节固定不变：

| 小节 | 内容 | 要点 |
|------|------|------|
| 0. 环境与目标 | python 路径、库版本、目标文件、本次增量要搬什么 | 一句话说清「在哪个文件新增哪几个函数」 |
| 1. 硬性要求 | 禁止逐元素 Python 循环；下标一律位置下标；全 GPU；只输出函数源码 | 违反即不可用，逐条列 |
| 2. 可复用的已有工具 | 已有函数的签名与语义 | **防止模型重写已有件** |
| 3. 需要实现的函数 | 每个函数的逐位语义 + 参数 + 返回 + **实现步骤（S1…Sn）** | 步骤要写到「照做即对」的粒度 |
| 4. 最小夹具与期望值 | 3–5 组手工可算的小夹具 + 期望数组 | **没有夹具，草稿无法自证** |
| 5. 交付要求 | 只输出函数、中文注释、空输入边界 | 明确不要 `__main__` / 测试代码 |

文件命名约定：`l0_gpu_spec{N}.txt`（N = 增量序号）。

### 步骤 2 — 发送给本地模型

用 **Python `urllib.request` 直发 JSON**，不用 PowerShell。

- 发送脚本：`l0_gpu_ask{N}.py`
- 产出文件：`l0_gpu_out{N}.py`

```python
import json, urllib.request

SPEC = r"C:\Users\macotai\AppData\Local\Temp\l0_gpu_spec3.txt"
OUT  = r"C:\Users\macotai\AppData\Local\Temp\l0_gpu_out3.py"

with open(SPEC, "r", encoding="utf-8") as f:
    prompt = f.read()
payload = {
    "model": "qwen2.5-coder:14b",
    "prompt": prompt,
    "stream": False,
    "options": {"temperature": 0.2, "num_ctx": 16384, "num_predict": 4096},
}
req = urllib.request.Request(
    "http://localhost:11434/api/generate",
    data=json.dumps(payload).encode("utf-8"),
    headers={"Content-Type": "application/json"},
)
with urllib.request.urlopen(req, timeout=3600) as r:
    body = json.loads(r.read().decode("utf-8"))
text = body.get("response", "")
with open(OUT, "w", encoding="utf-8") as f:
    f.write(text)
print("DONE chars=%d  eval_count=%s" % (len(text), body.get("eval_count")))
```

### 步骤 3 — 主 agent 审核（固定检查清单）

按序过一遍，逐项判「过 / 不过」：

1. **骨架完整性**：规范里要求的函数是否都在？实现步骤（S1…Sn）是否漏步？
2. **未定义引用**（最高频硬 bug）：草稿里用到的每个名字，是否都在草稿或「可复用工具」清单里定义过？
3. **逐元素循环**：是否出现 `for i in range(V)` / `for c in cands` 之类遍历节点·边·dart·候选的循环？（O(1) 次的固定轮数循环允许）
4. **下标语义**：是否混用了「原始 id」与「位置下标」？
5. **空输入边界**：空数组 / `m=0` / 空 mask 能否正常返回？（`.max()` 对空数组会抛异常，需守卫）
6. **框架细节**：CuPy 的 `lexsort` **只接受 2-D 数组、不接受 tuple、最后一行是主键**；`searchsorted` 返回 int64，索引前要降位。
7. **绕而存疑的写法**：语义正确但嵌套过深的向量化表达式 → 判为「可保留骨架思路、正文重写」。

审核结论只用三类措辞：**骨架正确** / **骨架缺口** / **硬 bug**。

### 步骤 4 — 重写落地

- 以草稿的**分步骨架**为起点（分步划分通常是对的，直接沿用）；
- 补上模型的缺失定义与守卫；
- 把嵌套过深的表达式换成**等价但可读**的写法；
- 中文注释与小节分隔（`# --- S1 … ---`）与本文件其余部分同风格。

### 步骤 5 — 验证（三级递进，全部通过才算完成）

| 级别 | 手段 | 说明 |
|------|------|------|
| ① 夹具 | `verify_fixtures()` | 用规范 §4 的手工期望值，**先跑这一步**——不经它不跑全量 |
| ② 逐位 | `verify_*_against_cpu()` | 与 CPU 参考实现比对环序 dict、`nid`、事件计数；多配置 × 多帧 |
| ③ 端到端 | `verify_frame_path()` | GPU 整条路径 vs 纯 CPU，逐帧 `state_hash` 一致 |
| 收尾 | 全量 `selftest=1` + 既有 CLI 回归 | 新增能力不得打破已有 CLI |

**测试配置矩阵**（沿用 L0 口径，可复用到其他层）：
`种子 × drive × cap × dmin × pairing × 穿刺` —— 每格 4 帧，且**同一格同时覆盖"有删除/无删除、有断边/无断边"**。

## 2. 协同原则

1. **本地模型只产出骨架**，不作判据。判据是 CPU 参考实现（`l0_core.py` / `combinatorial_proto.py`）。
2. **规范里必须带最小夹具**。手工可算的期望数组，是唯一能让草稿「自证」的东西；同时也是主 agent 落地后的第一道验证。
3. **逐位一致 = 环序 dict + `nid` + 事件计数**，三者缺一不可。`state_hash` 只覆盖环序，**不覆盖 `nid`**，故 `nid` 必须单独校验（否则新 id 编号漂移会推迟若干帧才炸）。
4. **结论立即冻结成「进度锚点」**，写进 `docs/L0L1L2_架构设计.md` §7：新增件清单、关键简化、等价性依据、验证读数、仍留在 CPU 的部分。
5. **不预设本地模型会失败**，但**假定草稿不可直接运行**——审核与重写是流程的固定环节，不是意外处理。

## 3. 本地模型草稿的已知失败模式（实测）

| # | 模式 | 实例 | 处置 |
|---|------|------|------|
| 1 | **引用未定义变量** | `rebuild_rings` 的 S3 用 `no_alive`，但从未定义 → 直接 `NameError` | 按规范补定义（`no_alive = int(alive.sum())`） |
| 2 | **向量化写法绕** | ragged 组内序号写成多层 `searchsorted(bincount(...))` 嵌套 | 保留骨架，正文换成「模板序 `argsort` + 组内 ok 前缀和 − 该候选之前的 ok 数」 |
| 3 | **夹具描述出错** | spec 第一版 B 组夹具的期望值写错、措辞不严 | 规范本身要被复核；夹具写错会让模型答错却看不出错 |
| 4 | **等价但冗余** | 用 `arange.repeat` 代替 `owner_of_dart(rot_ptr)` | 两者等价，可保留 |
| 5 | **发送通道** | PowerShell `Invoke-RestMethod` + `ConvertTo-Json` 转义 prompt 失败，报 `cannot unmarshal object into Go struct field GenerateRequest.prompt of type string` | 改用 Python `urllib.request`（见步骤 2），不折腾编码 |
