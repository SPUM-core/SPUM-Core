**版本状态**：正式发布

## 1. 版本号格式

```
<基底指纹>.<内容类型>.<A分>.<B分>.<C分>.<D分>.<LE>.<验证指纹>.<时间戳>
```

### 字段说明

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| 基底指纹 | 固定字符串 | SPUM 核心公设的 SHA256 前 8 位，确保基底不变 | `a7f3e2d8` |
| 内容类型 | 枚举 | `theory`, `graph`, `exp`, `data`, `dial`, `code`, `core` | `theory` |
| A 分 | 两位数（00–99） | 架构纯净度 | `98` |
| B 分 | 两位数（00–99） | 推导严密性 | `87` |
| C 分 | 两位数（00–99） | 归约完备度 | `76` |
| D 分 | 两位数（00–99） | 方法论透明度 | `83` |
| LE | 一位数（0–3） | 梯子依赖指数 | `1` |
| 验证指纹 | 12 位十六进制 | 内容 SHA256 的前 12 位，防篡改 | `a1b2c3d4e5f6` |
| 时间戳 | 10 位数字 | Unix 时间戳（秒） | `1743196800` |

**示例**：  
`a7f3e2d8.theory.98.87.76.83.1.a1b2c3d4e5f6.1743196800`

### 内容类型说明

| 类型 | 含义 | 评审要点 |
|------|------|----------|
| `theory` | 核心理论文档（knowledge.md, SPUM2610.md 等） | 四维全量评审 |
| `graph` | SPUM-图论文档与代码（08_SPUM_Graph_Theory.md, src/spum_graph/） | A 维度重点检查 L0.5 层与 L2 经典图论隔离 |
| `exp` | 实验脚本与结果（experiments/ 下各子目录） | A≥50, LE≤2 |
| `data` | 数据集与数据文档（.npz 等） | A 基准检查 |
| `dial` | AI 对话归档 | 宽松评审 |
| `code` | 通用代码（非图论/帧协议） | A/D 维度重点 |
| `core` | 帧协议代码（src/core/） | D 维度重点：帧状态透明度 + 回滚闭环 |

## 2. 四维评分规则

### 2.1 架构纯净度（A）

**定义**：概念体系是否仅包含 SPUM 原生实体（L0 本体层 + L0.5 SPUM-图论层），禁止引入 L2 旧范式实体作为基底。

**评分标尺**（00–99）：

| 分数段 | 等级 | 判定标准 |
|--------|------|----------|
| 90–99 | 圣典级 | 概念完全由 L0 节点、边、度数、离散帧、创生/湮灭事件 及 L0.5 FrameGraph、DanglingDetector 等原生概念构成 |
| 70–89 | 纯净级 | 概念原生，允许 L2 借用但已完整重定义为 L0 投影 |
| 50–69 | 过渡级 | 存在少量可归约的 L2 概念（已声明为借用但未完整归约） |
| 30–49 | 污染级 | 概念中混入旧物理实体（如同时假设空间粒子与场） |
| 10–29 | 寄生级 | 概念依赖旧实体（如"原粒子""能量守恒"为前提） |
| 0–9 | 废弃级 | 概念完全为旧实体（力、粒子、绝对时空） |

**L0.5 层特殊检查**（v5.0 新增）：
- SPUM-图论概念是否与 L2 经典图论混淆 → 出现"连通分量""聚类系数""最短路径"等未声明的经典图论概念，扣 20 分
- FrameGraph 五公理是否与 knowledge.md N022 定义一致 → 不一致扣 15 分
- 图论代码是否引用了 L2 图论库的核心概念作为推理前提 → 扣 10–20 分

**扣分细则**（从 100 分起扣）：
- 引入禁止基底实体（引力子、绝对时空、原粒子、场、力等）→ 直接降至 30 分以下
- 引入可归约辅助概念但未归约 → 扣 10–30 分
- L0.5 与 L2 图论混淆 → 扣 15–30 分（v5.0 新增）
- 使用数学工具但未声明工具属性 → 扣 5–10 分
- 公理存在循环或冗余 → 扣 10–20 分

**保留分**：即使基底污染，若现象层有探索价值，可保留 5–20 分作为探索分。

---

### 2.2 推导严密性（B）

**定义**：逻辑推导图是否无环、无悬空节点，层级跃迁是否可证。v5.0 扩展：是否通过双层闭合判据（δ < θ 且 Δμ < θ）。

**评分标尺**（00–99）：

| 分数段 | 等级 | 判定标准 |
|--------|------|----------|
| 90–99 | 完美 | 无循环、无悬空节点，所有层级跃迁有形式化证明，**且通过双层闭合判据** |
| 70–89 | 严谨 | 无循环、无悬空，少数边缘步骤依赖未证明假设，双层判据通过其一 |
| 50–69 | 基本闭合 | 主要推导链完整，个别步骤未展开，双层判据未验证 |
| 30–49 | 部分断裂 | 存在明显逻辑跳跃，依赖外部未归约理论 |
| 10–29 | 严重断裂 | 关键结论无推导，仅靠类比或断言 |
| 0–9 | 无推导 | 完全无逻辑链，仅现象罗列或信仰陈述 |

**双层闭合判据**（v5.0 新增，见 §2.5）：
- δ < θ_δ：边缘不完美（悬挂端密度）低于阈值
- Δμ < θ_μ：中心不完美（锚点漂移率）低于阈值
- 仅 δ 通过 → 不满足完整闭合，B 维度上限 85
- δ 和 Δμ 均通过 → 完整闭合，B 维度可达 90+

**扣分细则**（从 100 分起扣）：
- 循环定义（A→B→A）→ 每处扣 20 分
- 悬空节点（现象或结论无入边）→ 每个扣 10 分
- 层级跃迁无推导步骤 → 扣 30 分
- L2→L2 直接推理（未经过 L0 中介）→ 每处扣 30 分（v5.0 新增）
- 使用"偶然""显然"等模糊词代替推导 → 每处扣 5–10 分
- 双层判据未验证 → 不扣分，仅限制上限（v5.0 新增）

**保留分**：若整体框架有系统性但细节缺失，保留 20–40 分。

---

### 2.3 归约完备度（C）

**定义**：现象节点到公理节点的映射路径是否完整。v5.0 扩展：溯源到 N001-N022（v4.0 为 N001-N020）。

**评分标尺**（00–99）：

| 分数段 | 等级 | 判定标准 |
|--------|------|----------|
| 90–99 | 完全归约 | 所有宣称现象均有从 N001 出发经 22 节点的完整推导路径 |
| 70–89 | 主要归约 | 核心现象有路径，少数现象标记"待完善" |
| 50–69 | 部分归约 | 主要现象有定性映射，缺定量或形式化 |
| 30–49 | 生硬归约 | 使用 SPUM 词汇但逻辑依赖旧范式直觉 |
| 10–29 | 未归约 | 使用传统术语描述现象，未建立映射 |
| 0–9 | 无归约 | 现象与理论无关，或完全用旧理论解释 |

**v5.0 溯源的 22 节点**：N001-N022（参见 `network/nodes.txt`），新增节点 N021 拓扑认知、N022 SPUM-图论必须纳入归约路径。

**扣分细则**（从 100 分起扣）：
- 宣称现象无推导路径 → 每个扣 15 分
- 映射路径中存在"黑箱"步骤（如"结构产生意识"）→ 每处扣 20 分
- 使用未归约传统概念（熵、力）作为中介 → 每处扣 10 分
- 归约链未覆盖 N021/N022 → 扣 5–10 分（v5.0 新增）

**保留分**：若现象覆盖面广且尝试映射，保留 20–50 分。

---

### 2.4 方法论透明度（D）

**定义**：是否明确区分数学描述工具与物理实在。v5.0 扩展：帧协议状态是否透明可审计。

**评分标尺**（00–99）：

| 分数段 | 等级 | 判定标准 |
|--------|------|----------|
| 90–99 | 完全透明 | 严格区分数学形式与物理实在，工具声明清晰，**帧协议状态可审计** |
| 70–89 | 基本透明 | 多数工具声明，少数边界模糊，帧协议有记录但未完整审计 |
| 50–69 | 部分混淆 | 将数学量当作独立实体未加说明 |
| 30–49 | 严重混淆 | 数学形式与物理实体混用，无区分意识 |
| 10–29 | 工具即实体 | 认为数学结构就是物理实在（如"时空是黎曼流形"） |
| 0–9 | 无方法论自觉 | 完全未讨论工具与实体的关系 |

**帧协议透明度**（v5.0 新增）：
- 代码提交是否包含 FrameProtocol 帧状态记录 → 含记录 +10 分
- 是否通过 ReviewBridge 的评审闭环 → 通过 +5 分
- 评审结果 ReviewResult 是否可序列化审计 → 可审计 +5 分

**扣分细则**（从 100 分起扣）：
- 将数学量直接作为物理实体解释现象 → 扣 20 分
- 使用复杂数学形式未说明描述性质 → 扣 10 分
- 未声明离散-连续过渡是近似还是严格对应 → 扣 10 分
- 帧协议相关代码缺少 FrameState 记录 → 扣 10 分（v5.0 新增）

### 2.5 双层闭合验证标准（v5.0 新增）

**背景**：2026 年 N013/N016 实验证伪了"单靠 δ 下降可判定拓扑闭合"的假设。完整闭合必须同时满足两层判据。

**判定公式**：

```
闭合 = (δ < θ_δ) 且 (Δμ < θ_μ) 持续 N 帧
```

| 参数 | 定义 | 推荐阈值 | 来源 |
|------|------|----------|------|
| δ | 悬挂端密度 = 悬挂端数 / 总节点数 | θ_δ = 0.05 | FrameGraph.dangling_density() |
| Δμ | 锚点漂移率 = ||μ(t) - μ(t-1)|| | θ_μ = 0.01 | DanglingDetector 锚点漂移均值 |
| N | 连续满足帧数 | N_min = 3 | FrameProtocol 栈溢出阈值 |

**评分影响**：
- δ < θ_δ 且 Δμ < θ_μ：完整闭合 → B 维度可达 90+，C 维度 +5 分
- 仅 δ < θ_δ：边缘闭合 → B 维度上限 85，标记"中心不完美"
- 两者均不满足：无闭合 → B 维度上限 70
- 标准演化动力学中 Δμ < θ_μ 永不满足（锚点持续震荡）→ 符合 N013 不完美定理

**代码层实现**：`DanglingDetector.update()` 自动输出 δ 与 Δμ，`ReviewBridge.submit()` 可接入双层判据进行自动评审。

## 3. 梯子依赖指数（LE）

**测试方法**：移除所有传统物理学术语（力、场、粒子、能量、熵、波函数等）及经典图论术语（连通分量、最短路径、聚类系数等），观察逻辑图是否仍然连通。

**v5.0 扩展**：增加 L0.5 依赖检测——移除 L2 经典图论概念后，SPUM-图论逻辑是否完整。

| LE | 定义 | 判定标准 |
|----|------|----------|
| 0 | 无梯子 | 移除后逻辑图完整，所有概念已用 L0/L0.5 语言表达 |
| 1 | 方法论梯子 | 移除后仅数学工具/FrameGraph 保留，推导链仍完整 |
| 2 | 启发式梯子 | 存在非必要类比（如"水与冰""网络密度"），移除后影响理解但不破坏逻辑；或 L0.5 与 L2 图论混用但可分离 |
| 3 | 逻辑依赖 | 移除后推导断裂，必须依赖传统术语或经典图论概念作为中介 |

## 4. 验证指纹

- **生成方法**：对提交内容（文本、代码等）计算 SHA256 哈希，取前 12 位十六进制。
- **作用**：确保版本号与内容一一对应，防止篡改。任何修改必须重新生成版本号。

---

## 5. 自动化评分流程

采用 **AI 抽取 + 人工校对 + 脚本评分** 的混合模式：

1. **AI 抽取**：将理论文本转换为 JSON-LD 格式的逻辑图，包含：
   - 公理节点 A
   - 推导边 D
   - 归约映射 M（须覆盖 N001-N022）
   - 现象节点 P
2. **人工校对**：提交者借助可视化工具（如 NetworkX 图形）检查逻辑图准确性，确认后提交。
3. **脚本评分**：基于图算法自动计算四维得分与 LE 指数，输出版本号与详细报告。

**v5.0 集成**：评分流程与 `src/core/` 帧协议自动化深度集成：
- 帧协议（`FrameProtocol`）自动追踪推理帧状态（悬挂端数、层级分布、闭合判定）
- 评审桥接器（`ReviewBridge`）接收评审结果，自动执行 PASS/WARN/ROLLBACK 判定
- 回滚闭环：任一维度 < 50 或 LE ≥ 2 → `protocol.rollback()` 回退到上一闭合帧
- 所有结果可序列化为 JSON 审计记录

所有评分工具（Python + NetworkX + `src/spum_graph/` + `src/core/`）随 spum-core 仓库开源，确保评分可复现。

## 6. 仓库过滤策略

### 6.1 核心理论与代码（`src/`, `knowledge.md`, `SPUM2610.md`, `core/v1.0/`）

合并条件：
- A ≥ 70
- B ≥ 70
- C ≥ 70
- D ≥ 70
- LE ≤ 1

### 6.2 SPUM-图论层（`src/spum_graph/`, `core/v1.0/08_SPUM_Graph_Theory.md`）（v5.0 新增）

- 代码层（`src/spum_graph/`）：A ≥ 70, D ≥ 70, LE ≤ 1
- 文档层（`08_SPUM_Graph_Theory.md`）：A ≥ 75（重点 L0.5 纯净度）
- 与 L2 经典图论混淆 → 降为 draft 分支

### 6.3 帧协议层（`src/core/`）（v5.0 新增）

- A ≥ 70, D ≥ 80（重点帧协议透明度）
- 必须包含 `FrameState` 记录或 `ReviewResult` 评审结果
- LE ≤ 1

### 6.4 实验分支（`experiments/p0_*`, `p1_*`, `p2_*`, `n015_*`, `n016_*`）

- 要求 A ≥ 50，LE ≤ 2
- double-layer 判据验证实验（N015/N016）优先合并
- 其余维度不作强制，但需生成版本号与评分报告

### 6.5 草稿分支（`draft/`）

- 接纳暂态理论（如 A ≥ 70 但其他维度暂低）
- 版本号末尾附加 `-draft` 标记，例如：`a7f3e2d8.theory.85.45.60.70.1.a1b2c3d4e5f6.1743196800-draft`
- 允许迭代更新，直至达到核心库标准后迁移

### 6.6 数据与对话分支（`experiments/shared/`, `dial/`）

- 数据：A 基准检查，LE ≤ 2
- 对话归档：不强制过滤，但需生成版本号

## 7. 修订与演进

- 评分细则可根据 spum-core 社区共识定期修订，但版本号格式保持稳定

- AI 评分脚本与规则同步更新，保证历史版本可回溯
