## 二、已发现的攻击面

### 🟡 P1 — AI 对话 API 存在但认证可绕过？（中危）

**端点**: `POST www.zhihu.com/api/v4/chat`

**证据**:
- 返回 `401 AuthenticationError`（不是 404，说明端点真实存在）
- 带 `x-zse-93` 签名头时返回 `403 请求参数异常`（签名机制和主 API 相同）
- 需要的认证凭证: `x-zse-93` + `x-zse-96` 签名 + `z_c0` session

**潜力**:
如果攻破这个 API 的认证，就可以:
- 以用户身份向 AI 发送任意 Prompt
- 执行 Prompt Injection 获取系统信息
- 利用 AI 的 tool calling 能力（如果存在）访问内部系统

**瓶颈**: 需要逆向 x-zse-93/96 签名算法（非对称加密，难度高）

---

### 🟢 AI 入口卡公开接口（信息泄露）

**端点**: `GET www.zhihu.com/ai_ingress/ai_chat/get_guide_card`

**现状**: 公开可读，返回 JSON 格式的推荐问题列表和搜索链接

**示例响应**:
```json
{
  "query_list": [
    {"intro_word": "马克思主义最根本的逻辑是什么？", "link_url": "https://zhida.zhihu.com/search?q=..."},
    ...
  ]
}
```

**风险**: 低。该接口只返回推荐问题，不涉及用户数据。

---

### 🟡 OpenAPI Agent 系统（中危）

**端点**: `openapi.zhihu.com/openapi/agent/*`

**现状**:
- 有签名即可代用户发布想法到指定圈子
- 发布内容带"Agent 发布"标识
- 无法冒充用户身份发布（有标识）

**瓶颈**: 被限定在特定圈子，且内容和操作有明确标识

---

### AI 创作模块（信息收集）

**从 JS 发现的 AI 功能**:
- `ai_creation_title_adopt` — 标题生成
- `ai_creation_contentcheck` — 内容检查
- `ai_creation_assistant_panel` — 创作助手面板
- `ai_creation_intellige_typeset` — 智能排版

**这些接口都需要认证**，且需要 `__zse_ck` 签名。

## 三、SPUM 攻击路径分析

### 最佳路径: 种子投毒 → 知识库污染

```
步骤 1: 向知乎投稿包含毒化内容的文章/回答
步骤 2: 文章被收录进 AI 知识库（高概率，知乎直答会索引平台内容）
步骤 3: 用户向直答提问时，毒化内容被检索并纳入 LLM 上下文
步骤 4: Prompt Injection 在 LLM 内部执行 (间接注入)
```

**SPUM 语义**: 通过已有边（发布内容）建立新边（内容 → 知识库），再通过知识库影响 AI 节点的行为。

**可行性**: ✅ 中等偏高。知乎直答的知识库基于平台内容，发布一篇精心构造的文章，内容中嵌入诱导性指令，在用户提问相关话题时被触发。

### 第二路径: AI 对话 API 认证突破

```
需要逆向 x-zse-93/96 签名机制
→ 难度: 高
→ 收益: 高（获得 AI 对话权限）
```

### 第三路径: Agent 系统扩展

```
利用 OpenAPI Agent 做更复杂的操作
→ 需要发现更多未公开的 agent API
→ 目前被限制在发布想法
```

## 四、结论

### 直接可操作的漏洞（悬赏范围内）

| 编号 | 类型 | 真实性 | 严重度 | 操作性 |
|------|------|--------|--------|--------|
| 1 | CSRF 关注/取关/感谢 | ✅ 已确认 | 中危 | ✅ 可直接提交 |
| 2 | Members API 信息泄露 | ✅ 已确认 | 低-中危 | ✅ 可直接提交 |
| 3 | apm.zhihu.com CORS 配置缺陷 | ✅ 已确认 | 中危 | ✅ 可直接提交 |

### 建议

**知乎这个目标的深度测试边际收益已很低**。核心发现（CSRF + Members API）可以直接提交。如果想挖更深的漏洞（直接进服务器），建议换目标——选一个防护弱的站点，从零开始 SPUM 拓扑扫描，产出会高得多。
